# Описание нашей Firewall-логики (актуальное)

## Что мы сделали

Мы привели работу защиты к стабильной и предсказуемой схеме:

- Используется **одно постоянное правило Windows Firewall**: `RDP_BLOCK_ALL`.
- Правило **не пересоздается при каждом событии** и не меняет смысл работы.
- При новом бане в правило **добавляется IP** в общий список `RemoteIP`.
- При снятии бана IP **удаляется из этого же списка**.
- Источник истины по блокам: `block_list.log` + активные состояния банов в сервисе.

Идея соответствует вашей постановке: «создали одно правило при установке, дальше только обновляем список IP внутри него».

## Как работает сейчас

1. Сервис читает события неудачных RDP-логинов из Security Event Log.
2. Считает попытки по IP и применяет уровень блокировки по конфигу.
3. Если нужно заблокировать IP:
   - добавляет/обновляет запись бана,
   - синхронизирует `RDP_BLOCK_ALL`, добавляя IP в `RemoteIP`.
4. Когда бан истекает или IP разблокирован вручную:
   - запись бана снимается,
   - IP удаляется из `RDP_BLOCK_ALL`.

## Важная логика для активных сессий

Добавлено безопасное поведение для случая, когда с «вашего» IP кто-то атакует другой логин:

- Если IP принадлежит активной сессии **того же пользователя**, бан может быть пропущен (анти-self-block).
- Если с того же IP идёт атака на **другого пользователя**, IP всё равно банится.

Это устраняет конфликт: вы не выкидываете сами себя обычной активностью, но атака с вашего IP на чужой логин не остаётся без блокировки.

## Что это дало

- Предсказуемое поведение firewall без «ломающего» пересоздания правил.
- Быстрый и понятный контроль блоков в одном месте (`RDP_BLOCK_ALL`).
- Корректная реакция на brute-force с одного IP по разным логинам.
- Снижение риска рассинхронизации между логами блокировок и реальным firewall-состоянием.

## Где это в коде

- Сервисная логика банов и синхронизации firewall: [WinService/Program.cs](WinService/Program.cs)
- Логи и состояние:
  - `C:\ProgramData\RDPSecurityService\access.log`
  - `C:\ProgramData\RDPSecurityService\block_list.log`
  - `C:\ProgramData\RDPSecurityService\service.log`

## Быстрая проверка на сервере

Проверить текущее правило:

```powershell
netsh advfirewall firewall show rule name="RDP_BLOCK_ALL"
```

Проверить, что IP появляются/исчезают по факту бана/разбана в `RemoteIP`.

## Коротко для релиза

Наша firewall-модель: **single-rule aggregated blocklist**.

- Rule: `RDP_BLOCK_ALL`
- Add ban: добавить IP в `RemoteIP`
- Remove ban: удалить IP из `RemoteIP`
- No destructive re-create logic in normal flow
